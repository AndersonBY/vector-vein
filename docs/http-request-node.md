# HTTP 请求节点

在工作流编辑器的“工具”分类中添加“HTTP 请求”，可直接调用 HTTP 或 HTTPS 接口，并把状态码、响应头、响应文本或解析后的 JSON 连接到后续节点。

## 配置

请求方法和 URL 显示在节点上，其他输入位于“更多设置”中。URL 接受单个字符串，可包含原有查询参数；查询参数配置会追加到原有参数中，同名参数也会保留。

| 输入 | 默认值 | 用途 |
| --- | --- | --- |
| 请求方法 | GET | 支持 GET、POST、PUT、PATCH、DELETE、HEAD、OPTIONS。 |
| URL | 空 | 必填 HTTP 或 HTTPS 地址，支持本机服务。 |
| 请求头 | `{}` | JSON 对象，例如 `{"Accept":"application/json"}`；名称和字符串值需符合 HTTP 请求头格式。 |
| 查询参数 | `{}` | JSON 对象，值可以是字符串、数字、布尔值、null 或这些值的列表。 |
| 请求体格式 | 无请求体 | 可选 JSON、文本、表单。 |
| 请求体 | 空 | JSON 格式填写有效 JSON；文本格式直接填写内容；表单格式填写 JSON 对象，值为标量。无请求体时忽略此项。 |
| 超时 | 30 秒 | 允许 1–300 秒，作用于每个网络操作阶段。 |
| 跟随重定向 | 关闭 | 开启后跟随服务返回的重定向。 |
| HTTP 错误时失败 | 开启 | 收到 4xx 或 5xx 时停止节点；关闭后可将错误响应交给后续节点处理。 |

请求头、查询参数和表单请求体支持逐行添加、编辑和删除键值对，也可切换到 JSON 模式。请求头值始终为字符串；查询参数和表单条目可选择“文本”或“JSON”值类型，后者用于数字、布尔值、null（查询参数还支持标量列表）。例如文本 `0` 与 JSON `0` 分别保存为字符串和数字。

空名称、重复名称、非法请求头、无效 JSON 和不符合类型要求的值会在字段下显示错误，草稿不会被丢弃或自动修正。草稿可保存；在使用页或编辑器中点击运行时，会先检查未连接上游的配置，有错时不提交运行。修正 JSON 后才能切回键值对模式。切换请求体格式会保留原内容；“无请求体”时忽略但保留它。连接上游后关闭对应字段的字面值编辑，断开后恢复。旧工作流中的 JSON 字符串和对象可直接打开。

请求头和查询参数也可以直接连接上游对象。JSON 请求体可连接对象、数组、数字、布尔值或 null；手动输入 JSON 字符串时需包括双引号，例如 `"hello"`。数字 `0` 和布尔值 `false` 保持原类型。

调用使用应用已有的代理和 TLS 验证设置。节点不自动重试请求，避免重复发送可能修改数据的操作。请求中的认证信息由请求头等输入提供；工作流和运行记录会保存这些配置及响应，分享或导出前应移除私密信息。

## 输出和失败

| 输出 | 类型 |
| --- | --- |
| 状态码 | 整数 |
| 响应头 | 对象 |
| 响应文本 | 字符串 |
| 响应 JSON | 解析后的 JSON 值；无有效 JSON 时为 null。 |

响应上限为解压后 5 MiB，超过上限会使节点失败。HTTP 错误会先保留四项响应输出，再按“HTTP 错误时失败”设置决定是否停止。网络错误、超时或无效配置会显示失败原因，并阻止依赖此节点的下游执行；错误摘要不包含请求地址、请求头或服务返回的正文。

## GUI 验收

1. 添加 HTTP 请求节点，将“响应文本”连到文本输出节点，填写一个可访问的接口地址并运行，检查响应。
2. 使用带已有查询参数的地址，再添加查询参数对象，确认两者均生效。
3. 改为 POST 和 JSON 请求体，发送含中文、`0`、`false` 的内容，检查服务回显；修改后再次运行。
4. 使用返回 4xx 或 5xx 的接口，确认工作流失败且显示状态码。关闭“HTTP 错误时失败”后重试，确认下游可以处理错误响应。
5. 填入无效 JSON 或非 HTTP(S) 地址，确认出现输入错误；使用无法连接的地址，确认显示网络错误且不保留上次的成功输出。

本机回显服务即可完成这些检查，无需真实账户或外部接口。
