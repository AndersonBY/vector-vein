# 运行产物列表

工作流运行页在正常输出下方集中显示该次运行生成的本地文件，包含文件名、当前大小、来源节点，以及“打开”和“打开所在目录”操作。没有文件的运行不显示空列表。历史记录按所选运行加载产物，不使用当前工作流定义代替历史快照。

文件在生产节点成功写入后登记到该节点的 `data.artifacts`：

```json
{
  "path": "C:\\outputs\\report.txt",
  "name": "report.txt",
  "created_at": 1793000000000
}
```

登记点包括文档导出、HTML、非实时语音生成、PDF 页面渲染、图片生成与编辑、文件形式的截图、Python 节点收集的新文件、文档转换，以及视频下载完成回调。输入文件、已有音频播放、截图的 base64 内容和普通文本中的路径不计为生成文件。远程链接仍由原输出组件展示。

列表按本地路径去重，同一路径的多个来源节点均会保留。并行节点各自保存产物，已有的运行快照合并逻辑负责汇总；后续步骤失败不清除已经登记的文件。重新运行初始化空的产物记录，避免把上次输出字段中的路径当成本次新文件。

文件被移动或删除后，历史列表仍保留原文件名和来源，并显示“文件不存在”。打开文件操作不可用；原目录仍存在时可以打开所在目录。重新打开同一条历史记录会刷新文件是否存在；执行打开操作时也会再次验证。

运行记录保存文件引用，文件内容仍位于原位置。列表不会移动、复制、删除或版本化文件；同一路径之后被显式覆盖时，历史记录打开的是该路径当前的文件。文件大小也反映当前文件状态。

## 接口

- `workflow_run_record.list_artifacts({rid})` 返回 `data.artifacts`。每行包含 `path`、`name`、`size`、`exists`、`parent_exists`、`created_at` 和 `sources`。每个来源包含 `node_id`、`node_type` 和自定义 `title`。
- `workflow_run_record.open_artifact({rid,path,action})` 的 `action` 为 `open` 或 `folder`。只允许操作该条运行记录中登记的文件引用，并在操作时重新检查文件或目录。它不接受任意路径、网址或命令。

没有新产物字段的旧记录，仅对成功执行的文档、Python 和格式转换节点读取已知文件输出字段。无法证明生成归属的普通输出不会列入。新的空产物记录具有优先级，不会回退到旧路径。

## GUI 验收

1. 运行文档导出和 Python 文件生成节点，确认输出文件集中列出，文件名、大小和来源正确；点击打开文件及所在目录。
2. 重新运行后切换两条历史记录，确认各自只显示对应运行的文件。普通无文件工作流不出现文件列表，节点时间线仍默认隐藏。
3. 在文件生成后让下游步骤失败，确认已有文件仍可查看。
4. 在独立测试目录中移动一个测试文件，重新打开原运行记录，确认缺失行保留、打开文件禁用，目录操作按目录是否存在决定。
