# 聊天失败与连接中断

模型请求失败、连接关闭或等待数据超时时，聊天会结束加载，保留已收到的正文和推理内容，并在该条助手消息下显示原因及“重试”。失败状态写入消息记录，重新打开会话仍可查看；失败的部分回复不会作为已完成的助手回答发送给后续模型请求。

重试使用已有的重新生成接口，在同一条用户消息下创建新的助手回答。旧失败记录保留在消息分页中。每次生成使用独立 WebSocket，不自动重连或重发；发送、重试和追加回答在当前请求未结束时互斥。发送消息或创建会话失败时，输入内容和附件保留。

建立连接最多等待 15 秒，收到任何数据后按 180 秒无数据超时计时；持续有数据的回复不受总时长限制。离开会话会关闭该次连接，服务端停止对应生成并保存已经收到的内容。已经完成的回复不会被迟到的断线通知改成失败。

## 消息与接口

- 助手消息复用状态 `F` 表示失败，`metadata.error` 包含 `code` 和经过脱敏、长度限制的 `message`。生成失败时不保留可执行的工作流调用。
- 服务端先保存结束状态，再发送 `{end: true, mid, status, content, reasoning_content, model, ...}`。失败包含 `error`；成功保持 `S`，等待工作流调用保持 `W`。
- `message.done_notice({mid})` 幂等返回已保存的消息，兼容旧的响应缓存；缓存缺失或损坏不会抛出解析错误。
- `message.fail_notice({mid, cid, code, content})` 只接受连接失败、连接关闭或超时通知，仅能结束该会话中仍待处理的助手消息。已结束的消息直接返回当前状态。

## GUI 验收

1. 使用本机模拟端点正常回复，确认正文完整、加载结束，仍能继续发送。
2. 模拟请求失败，确认空回复也显示错误和重试；重新打开会话，失败记录仍在。
3. 模拟输出部分正文后失败，确认已生成内容保留，生成标记结束；重试成功后可分页查看旧失败。
4. 在生成期间中断 WebSocket，确认界面结束加载、保留部分内容且没有自动重发。
5. 在等待或重试期间切换会话，确认旧请求不会更新新会话，旧会话重开后显示结束状态。
6. 模拟消息创建失败，确认输入与附件仍在，发送按钮恢复可用。

自动测试覆盖 WebSocket 生命周期、计时器、迟到响应、重试定位、错误文本转义、持久化、失败历史过滤和正常工作流交接。
