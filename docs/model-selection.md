# Model selection

Agent settings, chat and Universal LLM nodes use `ModelPicker.vue`: a compact model/reasoning button opens the Default, High performance, Low cost and Custom menu. Custom opens an 800px dialog containing the shared `ModelSelector.vue` provider/model columns. The dialog edits a draft; cancel leaves the current pair unchanged and confirmation requires an available pair. Chat changes update locally only after the save succeeds.

Model presets are configured under Settings → Model presets and stored in `setting.data.model_preferences`. Each entry contains `model_provider` and `model`. Empty or unavailable presets are disabled. Choosing a preset saves a snapshot of its actual provider/model pair and the preference name; later preset edits do not rewrite existing agents, chats or workflow nodes. If a saved pair differs from its named preset, the picker displays it as Custom. Settings saves validate enabled models and local-family membership before persistence, and publish the settings store/catalog only after success.

Reasoning effort is stored in Agent/conversation settings and the workflow `reasoning_effort` field. Default omits the API parameter. Explicit choices pass through to both streaming and non-streaming workflow calls and chat calls; provider-specific translation remains in vv-llm. The slider uses the selected model's reported `capabilities.reasoning_efforts`. Older catalogs without that metadata keep the generic list. Switching to another model resets an unsupported effort only on that explicit user choice. Loading or refreshing catalogs does not change saved settings.

Fixed-provider and flattened model fields use `ModelSelect.vue`, a searchable single-model select. Both components leave stored values unchanged until the user selects or clears them.

Workflow model fields retain their stored values when mounted, restored, or refreshed from the settings catalog. A missing model is shown as unavailable only after a successful catalog load. Empty model fields stay empty; the catalog does not select its first entry. Existing provider-specific template defaults remain defaults for new nodes. Universal and custom model templates start with an empty model.

The custom dialog clears its draft model only when the user chooses a different provider; clicking the selected provider retains its model. Custom/local model family choices remain searchable and clear their model on an explicit family change. Restoring a provider or family through workflow history does not clear its model. Missing providers and families remain visible with an unavailable hint.

Model catalog options are computed from current settings, including enabled models and multimodal eligibility. The hydration helpers update options without replacing field values. Provider, family, and model fields retain their stored values and connection handles. The Universal LLM picker sits at the right of the model field heading. Its separate provider field is shown only when exposed in the run interface or connected by an existing edge. Agent settings place the picker at the right of the model section heading. Capability information has a horizontal inset inside workflow nodes and can wrap when space is limited.

Chat model changes use a draft. Changing its provider clears the draft model; canceling restores the conversation's existing selection. Confirmation requires an available provider/model pair. A saved conversation updates its displayed selection only after the save succeeds; a failed save retains the draft for retry. Replies from an earlier conversation or an unmounted selector do not update the current conversation. New conversations use the draft locally until created.

Search matches provider names, model names and IDs without case sensitivity. Searching does not change the selected pair. Disabled and loading controls cannot change it. Explicitly disabled local models are excluded from both chat and workflow family choices; family models without local backend metadata remain selectable. Automated coverage is in `frontend/tests/modelSelection.test.js` and `frontend/tests/agentSettings.test.js`.
